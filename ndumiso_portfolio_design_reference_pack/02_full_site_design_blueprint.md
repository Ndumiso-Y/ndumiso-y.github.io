# NDUMISO YEDWA PORTFOLIO — DESIGN CONTINUATION BLUEPRINT

## North star

A cinematic/editorial portfolio that helps SMEs, non-profits and community organisations understand the designer, trust authentic work and contact him quickly. The approved hero's visual vocabulary should carry through all seven sections, but **not** as seven identical hero blocks or a generic SaaS card dashboard.

## Global visual principles

- Editorial hierarchy over ornamentation. Prioritise readable typography, large genuine images and clear whitespace.
- Surface family: off-white / pale neutral + restrained solid blue-teal + charcoal / white type as required by actual contrast. Use only subtle *tonal falloff* where needed; avoid bright glows or random gradient geometry.
- Interaction family: transparent frosted-glass pill navigation and concise proof/skills controls, but not every element needs glass styling.
- Image family: original photos and verified portfolio visual artefacts, framed accurately. Do not invent people, branded work or evidence.
- Mobile composition is intentional rather than a scaled desktop collage. Make name and a meaningful portion of portrait visible near the first fold; keep quick access to navigation and primary contact CTA.
- Keep copy factual and accessible in real DOM text, every button an actual control.

## Section-by-section art direction (proposed, pending individual review)

### 01 — HERO (visual concept locked)
Use `approved_hero_reference.png`. Read the reference lock. Display authentic portrait and actual QR; don't use AI mockup imagery as production asset. Four curated image-led section shortcuts and glass skills-strip are previews only; actual long-form content stays in its original sections.

### 02 — ABOUT
Build one calm editorial introduction rather than a 4,500 px stack of similarly weighted items. Keep **all existing biography copy, skill details and recognition content**. Use a portrait or real brand element as an anchor, but do not create a new photographic scene. Organise Skills & Tools into a compact, accessible responsive grouping that can reveal each description; retain all 11 existing skill descriptions. Give Black Umbrellas, Treehouse sponsorship and Techdegree recognitions a clear evidence-gallery treatment; preserve click-to-expand modals, original letters/images, external links and zoom functionality. Evidence should remain inspectable, not hidden behind a new design.

### 03 — WEBSITES
Make existing website work the principal proof. Use large, uncropped **wide-aspect screenshots** and restrained editorial project captions/links. Respect original approximately 1.9:1 screenshot aspect ratio instead of forcing 4:3. Preserve all six website projects, names, approved copy, destinations and images. Desktop could alternate wide image/text compositions; mobile uses single column with large preview and legible link.

### 04 — GRAPHICS & BRANDING
A premium visual gallery: authentic logo cases, PDF/slides links, graphics and campaign imagery. Retain every existing graphics item and current gallery/lightbox functionality. Use a coherent typographic and gutter system, but adapt image framing to each asset's native aspect ratio rather than crop valuable work. No generated brand assets as stand-ins.

### 05 — SOCIAL MEDIA MANAGEMENT
Use recognizable original social visuals as case studies, with supporting role/activity descriptions and preserved existing external links. Keep The Village Economy Indaba and Easy Documents content and media. Clear grouping, restrained typography, optional compact expandable proof where it improves scanning; no unverified growth statistics.

### 06 — LEARNING JOURNEY
Preserve all eight Treehouse projects, full descriptions, audio walkthroughs, video, external demo links and sequence. Use a responsive gallery or list that never clips titles at 375/390 px. Make project playback and inspect controls keyboard/touch-accessible. Avoid forced wide fixed cards and nav arrows that obscure content.

### 07 — CONTACT
Continue the restrained editorial design into a clear final action area. Preserve the existing contact card, WhatsApp-first hierarchy, e-card/VCF and all existing contact and social links. Keep content accurate and the CTA easy to access on mobile. Any message form, if existing, must retain current delivery behaviour; no claim of successful sending without actual delivery.

## Design approval sequence

1. Lock approved hero reference in a project-local `02_reference_lock.md`.
2. Design/review About, then Websites, Graphics, Social, Learning and Contact, using *the same global visual principles but different section anatomy suited to content*.
3. Record each approved section in a reference register with owner acceptance; only then hand off the bounded Gate 1 static build (or separately approved component pilot) to Claude Code.
4. Claude Code must inspect repo and assets, protect original content/functionality, checkpoint to a safe branch and produce screenshots + visual diff evidence at 1440 / 1024 / 768 / 390.
5. Gate 2 static visual acceptance remains separate from motion, dynamic features and release.

## No-loss acceptance checklist

- Count and compare all seven headings/anchors and all current text blocks and URLs before/after.
- Compare every source asset path and used photo/PDF/audio/video against baseline inventory.
- Verify Black Umbrellas, Treehouse award and Techdegree evidence/lightbox/zoom/external links.
- Verify six website previews, graphics gallery, social content and all eight learning projects with audio and video.
- Verify WhatsApp-first contact, QR, VCF and analytics.
- Verify 44px touch accessibility target, responsive navigation, image-crop fidelity, no horizontal overflow, keyboard controls and reduction of unnecessary asset weight.
- No website deletion, live deployment or auto-approval based solely on a generated mockup.
